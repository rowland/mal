# Decision log

## 2026-09-12 — accepted product decisions

- D-001: Working name is Mal (말).
- D-002: Personal offline macOS app; five banks of 500 sense entries each.
- D-003: YAML authoring, strict grading with override, system pronunciation in v1.
- D-004: Eight multiple-choice options, configurable to 4/6/8/10. Distractors use full selected banks.
- D-005: Manual answer-mode switching; independent scheduling and mastery for every direction × mode.
- D-006: Parts of speech are filters, not weights. Default all.
- D-007: Continuous rotation, not daily budgets. Correct answers auto-advance.
- D-008: Repository Markdown project tracking; no external issue service.

## 2026-09-12 — implementation decisions

- D-009: Swift Package Manager provides an Xcode-openable project and CLI build/test. A packaging script produces a native ad-hoc-signed app. No generated Xcode project dependency.
- D-010: MalCore imports only Foundation. All grading, choice selection, queue and schedule decisions are pure functions. Tests inject timestamps and seeded randomness.
- D-011: SQLite via the system C library, serialized on the main actor for this local app. JSON domain payloads are stored in separate content/state/event tables. Versioned schema and event scheduler version support future migration.
- D-012: Backups use SQLite's backup API and finish with DELETE journal mode so a read-only backup needs no WAL/SHM sidecars. This fixed DEF-001 caught by integration tests.
- D-013: The initial scheduler is the explicitly specified transparent algorithm, not FSRS. Changes require a new scheduler version and regression fixtures.
- D-014: Learning-pool limits count all stored learning/relearning cards for a track, including deselected banks/categories; settings explain this. No progress is deleted when filtering.
- D-015: Retry spacing yields to available alternative cards. With no alternatives, minimum time still applies. The immediately previous sense remains excluded until an explicit Check again when idle.
- D-016: The 50-card batch counts submitted answers in the current session; it is a pause point, not a daily limit. Pool sizes and schedules survive restart; session batch counters do not.
- D-017: YAML entries use bank-namespaced stable IDs; do not regenerate published IDs or move entries between namespaces. Semantic replacements receive new IDs. The first content manifest freezes assignments for later editorial updates.
- D-018: Dataset matching is not linguistic verification. Bundled candidate vocabulary remains draft until sense, aliases, labels and forms are checked. No silent promotion to verified based on automated schema checks.
- D-019: “Accept my answer” replaces the last wrong grade transactionally, retaining an undone audit record. Saving an alias is part of that transaction. Undoing the corrected grade does not delete an explicitly saved alias.
- D-020: Mode/filter changes exclude the currently presented sense, even if ungraded. Source attribution stays in the bank browser; study feedback shows usage notes only.
- D-021: Retired entries retain history but do not count against the active learning pool. Still-active entries in deselected banks/categories do count.
- D-022: Native field editor captures marked-text state at the beginning of Return handling; both pre-event and current composition states prevent submission. Repeated study keys do not cascade grades.
- D-023: Imported IDs cannot change bank ownership, including when bank namespaces are nested. The `mal` root is also reserved.
- D-024: Package into a temporary staging directory, verify the signature, then publish. Retain the previous app for rollback. Never overwrite a working package with a partially built one.

- D-037: With Auto enabled, incorrect English-to-Korean answers speak the submitted word with question punctuation, then the correct lemma in a separate utterance after a 0.35-second pause. Use the installed voice's question prosody; no unnatural whole-word pitch shift. Correct answers remain a single utterance. Applies to selection and write-in; Auto off stays silent.

## Actual form practice — 2026-09-14

- D-038: Conjugated forms are study material, not merely alternate accepted answers. - D-039: Korean prompts and answer choices use explicit category-matching forms, randomized among listed variants. Corrections and speech use that same displayed form. Focused Korean write-in requires a matching labeled form; vocabulary aliases cannot bypass it. Nouns/adverbs remain uninflected and share their original progress. Number/counter attributives use their own category where listed.
- D-040: Schedule categories independently per sense/direction/mode. Preserve stable vocabulary IDs; append category identity to new storage keys. Do not promote new form mastery based on dictionary knowledge. Variants/synonyms within a category share that category's learning state. The selected style controls the review pool; other style progress waits intact.
- D-041: Keep YAML schema v1: speechLevel/honorific/attributive already express the supported present affirmative categories. Missing forms are skipped with a count; no automatic conjugation fallback. This iteration does not add past/future, negative, imperative, interrogative or connective practice.
- D-042: Upgrade SQLite to version 2 with an automatic pre-migration backup and transactional version marker. New optional formStyle in keys/settings decodes legacy JSON. The version bump protects users from older apps ignoring form identity; restore accepts v1/v2 and leaves live storage at v2.
- D-043: Correct 12 honorific labels across 마시다, 가깝다 and 고맙다; Novice contentVersion 3→4, IDs and verification status unchanged. See form-label-corrections-001.json for exact changes/sources. Coverage counts are not linguistic verification. The frozen initial assembly script used suffix/table-count heuristics that caused these labels; do not rerun it over published banks.

- D-044: Reverse grading also considers identical displayed conjugations across different lemmas of the same part of speech. Accept their explicitly listed English meanings and exclude those meanings/synonyms from distractors. This avoids unfair cards when a conjugation is ambiguous even though dictionary lemmas differ.

- D-045 (2026-09-16): New selections show an introduction with the actual Korean form, English meanings, dictionary lemma when different, and sense cue. Continue/Return opens the same card's quiz. No grade, accuracy change, learning step or answer-history record is created by reading/continuing. Newness is per sense/form/direction/mode, matching the queue. If abandoned before grading, an introduction can appear again after restart; existing graded tracks go straight to quiz. Undo returns to the quiz for regrading. Auto speaks Korean introductions in either direction.

- D-046: Scheduler v2 adds short reinforcement after the first correct learning answer, due after three intervening graded answers. This recall takes priority over new insertion, while due relearning/reviews retain priority. A short success leaves learning step 1 and starts the ten-minute wait; it does not substitute for timed learning steps. If ten minutes elapsed before the repeat, use the normal timed step instead. Failure resets learning as before.
- D-047: Persist optional reinforceAfterSequence in LearningState, preserving legacy decoding and undo snapshots. Existing scheduled dates remain unchanged. ## Dual-clock scheduling — 2026-09-16

- D-048: Scheduler v3 supersedes D-046/047. Time OR graded-answer distance triggers every learning and maintenance review. Learning intervals are 1m/3, 5m/8, 20m/20, 6h/50, 1d/100, then 3d/200 maintenance. Correct answers advance one step, including iteration-triggered checks. Maintenance never ends; use the existing mode-specific accuracy multipliers for both clocks, capped at 180 days and max(1000, 4×introduced track cards) answers.
- D-049: Learning mistakes step back two, retrying at 30s/3 answers. Maintenance mistakes save both intervals, then require three relearning successes with 30s/3, 5m/8, 20m/20 spacing; resume half saved intervals, minimum 1d/50. A repeated relearning error restarts the checks without discarding the saved intervals.
- D-050: Default four words awaiting first repeat replaces the old pool target. Due cards precede new except one new per five graded answers when capacity permits. With no due cards, introduce immediately within capacity; otherwise repeat the oldest early-learning card. Filtering/retirement removes cards from the capacity calculation without deleting their progress. Single-word banks may repeat their only sense; larger pools exclude the preceding sense.
- D-051: SQLite v3 adds an attempt clock_track column. Counters derive from non-undone attempts and are isolated by direction, form style and mode. Uninflected words still share their original schedule: its iteration deadline follows the style in which it was last answered. Introductions/replays never increment counters. Atomic overrides retain the original clock; undo reverses it. New insertion cadence derives from persisted attempts and survives restart.
- D-052: Back up v1/v2 databases before migration. Preserve existing due dates, accuracy and history; initialize iteration deadlines from current local counts. Legacy learning step 2 maps to new step 4; existing maintenance starts with a 200-answer interval. Old undo snapshots upgrade only when restored. Raw phase value "review" stays compatible, while code calls it maintenance. Restore accepts v1/v2/v3 and upgrades the restored database. These defaults are product heuristics to refine through user testing, not a validated memory model.

- D-053: Supersedes the five-answer new-word exception in D-050/051. All eligible due cards (learning, relearning and maintenance, by either clock) precede introductions. Introductions resume automatically once none are due, subject to first-repeat capacity. No daily cap; deadlines and stored progress are unchanged.

- D-054 (2026-09-17): Add I don’t know (⌘K) during either quiz mode. Record one unsuccessful recall using the normal failure schedule, reveal the introduction with pronunciation, and make Continue advance instead of testing the revealed answer immediately. Exclude that sense from the immediate next selection, even in a single-word bank (show the waiting state when necessary). Hide the action while introducing or showing feedback; repeated activation cannot grade twice. Auto pronunciation reads the revealed Korean form in either direction. Undo restores the prior schedule/counter. History identifies the action via the reserved empty answer plus correct=false; the normal UI never submits empty text. This uses existing storage and backup semantics without a schema migration. No personal alias is created.

- D-055 (2026-09-17): English→Korean write-in gains Speak Korean / Stop (⌘⇧R). Use macOS 26 SpeechAnalyzer + SpeechTranscriber with ko-KR, local processing only, no server fallback. Runtime probe found legacy SFSpeechRecognizer on-device=false but SpeechTranscriber supports ko_KR; only English models were installed. Offer an explicit Download Korean speech model button when missing. Apple manages the model; download needs internet, transcription does not. No microphone opens during model installation. System download can continue after leaving setup.
- D-056: Recognition produces an editable draft, never a grade or history event. Stop finalizes pending recognition; Return while active stops rather than submits. Disable editing during recording/finalization, then preserve existing IME-safe Return submission. Strip trailing sentence punctuation from dictated drafts only; preserve words, spaces and negation. Never bias recognition toward the expected answer. Speech input shares write-in progress and is not a pronunciation assessment.
- D-057: Stop synthesized speech before microphone capture; suppress playback while dictation is active. End recording after 20 seconds, bound finalization to five seconds, and cancel on card/mode change, undo, unknown-word action, history/library display, leaving the view or app deactivation. Session IDs reject late callbacks. Convert microphone buffers into independent analyzer-format buffers before asynchronous consumption. Microphone permission is requested only after explicit Speak Korean and available assets. Denial/failure leaves typing available; no recorded audio files are retained.

Speech implementation references: https://developer.apple.com/documentation/speech/speechanalyzer and https://developer.apple.com/documentation/speech/assetinventory (plus installed macOS 26 SDK interfaces). The newer API avoids the unavailable legacy Korean on-device model.
